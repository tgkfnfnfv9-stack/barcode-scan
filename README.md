# 会社バーコードスキャン｜株式会社小林機械

機械の銘板バーコードを Android／iPhone で読み取り、社内ページ（機械在庫・在庫板）へ誘導する現場用ツールです。
読み取りエンジンは端末内で完結（オフライン動作）、単一の `index.html` だけで動きます。機械情報・社員認証の取得にはネット接続が必要です。

**公開URL：** https://tgkfnfnfv9-stack.github.io/barcode-scan/

---

## 使い方

1. 上記URLを Android の Chrome または iPhone の Safari で開く（ホーム画面に追加すると便利）
2. あらかじめ使用中のブラウザで `kkmt.co.jp/staff` にログインしておく
3. 画面下の「スキャン」を押し、カメラの使用を許可する
4. バーコード全体を枠に合わせる。撮影・確定操作は不要
5. 読み取るとカメラが自動で閉じ、コードを履歴に登録して一覧へ戻る（最新が一番上）
6. 「スキャン」で次の機械を読み取る
7. 各行の「機械在庫へ」または「在庫板へ」を押すと、該当ページが開く

「登録」は、このツールの端末内の読み取り履歴への追加です。会社の在庫データを新規作成・更新する処理ではありません。

### 読み取りに困ったとき

- カメラを開いている間は自動で再試行する。バーコード全体が写る距離で、少し静止させる
- 「アルバムから選ぶ」「直接入力して登録」も使用可能
- カメラが許可されていない場合は、Safari／Chromeのサイト設定でカメラを許可する
- アプリを切り替えたときやカメラが中断されたときは停止する。戻ったらスキャンボタンで再開する
- 連続スキャンにはHTTPSと対応ブラウザが必要。カメラ映像は読み取りのため端末内で処理し、サーバーには送信しない

### 主な機能

- 読み取り履歴が積み上がる（同じコードは重複せず先頭へ移動）
- カメラ映像を繰り返し解析し、同じ機械番号を別フレームで確認してから1件だけ自動登録
- 読み取り成功・閉じる・画面を離れる操作でカメラを停止
- 登録後は結果を表示し、画面下の「スキャン」から再開できる
- 各コードから「機械在庫」「在庫板」の両方へ移動可能
- 個別削除（✕）／すべてリセット。写真解析中のリセットや画面離脱は解析を中止し、古い結果で履歴を復活させない
- 「すべてコピー」で全バーコードを1行1コードの形式でコピー（事務所へ送る用）
- 履歴は端末内に保存（閉じても更新しても残る）
- 社員ログイン中は現在価格（価格の種類も表示）・非公開価格・一時価格・価格メモ・メモを各履歴に常時表示。未ログイン時は社員ログイン案内に切り替え
- 価格メモとメモは各3行まで表示し、長い場合だけ灰色の「続きあり」を表示。「詳細を見る」で全文を確認できる

## 更新方法

`index.html` を新しい版で上書きコミットするだけで、数分後に公開URLへ自動反映されます（URLは変わりません）。

2. 鉛筆（Edit）または「Upload files」で新しい版に差し替え
3. 「Commit changes（変更をコミット）」で保存

## 技術メモ

- 単一 HTML（CDN・ネット依存なし）。読み取りエンジンは ZXing-C++（WASM）を base64 で埋め込み
- 遷移先
  - 機械在庫：`https://www.kkmt.co.jp/staff/stocks/short_search?barcode=<コード>`
  - 在庫板：`https://www.kkmt.co.jp/staff/stock_boards/short_search?barcode=<コード>`
- 印字と符号化値が異なる機械は、`index.html` 内の `OVERRIDE_MAP` に登録して対応

### カメラの読み取り改善

- 操作は「スキャン」で開いてバーコードをかざすだけ。ズーム・ライト・カメラ切替は使用しない。
- 背面カメラを優先し、1920×1080・30fpsを希望する。縦持ちでも取得条件を入れ替えず、対応端末ではブラウザによる映像の切り抜き・引き伸ばしを避ける。実際の解像度は端末に依存し、未対応の場合は基本設定で起動する。
- 対応カメラでは連続オートフォーカスと自動露出を有効にする。連続AFが非対応、または設定が拒否された場合は、単発AFに対応していれば起動時に1回要求する。単発AFは他の調整後に行い、後続の設定で繰り返さない。
- ブラウザが `pointsOfInterest` を認識し、自動AFに対応する場合は、読み取り枠の中央を自動調整の対象として指定する。端末によっては指定が反映されない。設定に失敗したり応答が遅れたりしても、読み取りは続ける。
- TORQUEを含む機種ごとの対応状況はカメラAPIから判断する。写真から推測した型番やレンズ番号でカメラを切り替えない。
- 中央の帯は元の画素のまま解析し、細いバーが縮小で消えることを防ぐ。ガイドはこの解析範囲の内側に表示する。定期的に映像全体も解析する。
- 未加工の映像と、銘板の明暗に合わせて補正した映像を交互に解析する。明るい銘板の白飛び・暗い銘板の黒潰れを避け、補正は最大4倍に制限する。ほぼ無地の映像は増幅しない。
- 解析画像は約120万画素までに抑える。中央の帯は幅3840pxまで等倍を保ち、全体解析は長辺1920pxまでに縮小する。
- 同じ番号を別の映像フレームで確認してから登録する。ぼやけるときはレンズを拭き、バーコード全体が枠に入る距離まで少し離して静止する。

### 開発時の確認

Node.js 18以降で `node --test tests/live-scan.test.cjs` を実行する。
カメラとDOMを模擬し、自動登録、重複防止、詳細開閉の位置保持、メモの省略、認証期限切れ・別タブのログアウト、履歴復元、手入力、APIタイムアウト、古い非同期結果の無視、権限エラー、画面離脱時の停止、写真読み取りを確認する。

GitHub Actions では Chromium と WebKit でも、履歴の下のカードの詳細開閉、画面幅変更時の3行メモ、認証期限切れ、画面復帰時の認証同期、読み取りエンジン初期化失敗をテストデータで確認する（実際の社員APIには接続しない）。ローカルで同じ確認を行う場合は `npm install --no-save --package-lock=false playwright@1.62.1`、`npx playwright install --with-deps chromium webkit`、`node --test tests/browser-layout.test.cjs tests/browser-camera.test.cjs` を実行する。
端末ごとのピント・解像度・読み取り速度と画面表示は、iPhoneなどの実機でも確認する。

カメラの回帰テストは、取得条件とピント設定の維持、未対応設定、権限拒否、終了後の非同期応答、一時的な映像停止、別フレーム確認を検証する。ブラウザでは生成した細いバー・薄い印字・軽いぼかしのあるバーコードを内蔵WASMで読み取り、変更前の画像処理では読めなかった条件も確認する。実際のレンズのピントや暗所性能は、模擬映像では検証できない。

実機では Android Chrome と iPhone Safari で、通常・暗所・反射する銘板、近距離／少し離した距離、縦横表示、閉じる／再開を確認する。
